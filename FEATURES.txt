STELLENBOSCH WARD MAP — FEATURES & CAPABILITIES
================================================

OVERVIEW
--------
An interactive, single-page web map of the 23 electoral wards of
Stellenbosch Municipality. Static site (HTML/CSS/vanilla JS + Leaflet),
no build step, no backend. One page (index.html) serves two modes via
the `ward` URL query parameter.

MODES
-----
- All-wards overview: index.html, index.html?ward=all, or no parameter.
  Shows every ward boundary and all voting stations.
- Single ward: index.html?ward=N  (N = 1..23). Shows that ward's
  boundary, its voting districts (VDs), voting stations, and a
  demographics panel.
- Invalid/out-of-range ward -> friendly error with a link back.

DATA SOURCES
------------
- Ward boundaries: Western Cape Government ArcGIS MapServer (sourced
  from the Municipal Demarcation Board). Primary layer; if it fails the
  map shows an error.
- Voting districts & stations: IEC (Electoral Commission) GIS API.
  Non-fatal: the map still works and a notice explains what's missing.
  All-wards mode fetches all 23 wards in parallel and tolerates partial
  failure.
- Reference data (local JSON): councillors.json (name, phone, party),
  demographics.json (population + census breakdowns per ward). Non-fatal.

MAP INTERACTION
---------------
- Base layers: OpenStreetMap (default) and Google Satellite, switchable.
- Polygon outlines recolour automatically for contrast (white on
  satellite, brand colours otherwise).
- Continuous (fractional) zoom for tight framing.
- All-wards: hover a ward to highlight it and show a mouse-following
  tooltip (ward number, councillor, population); click a ward to open
  its single-ward view.
- Single ward: hover a voting district to highlight it and show its VD
  number; click a voting station marker for a popup (name, VD, address,
  type).
- Feature labels (ward names / VD numbers) are auto-placed at an
  interior point of each polygon's on-screen area, hidden when they
  don't fit or would overlap a higher-priority label.

CUSTOM "TOOLS" CONTROL (top-left, collapsible)
----------------------------------------------
- Zoom in / Zoom out.
- Zoom to area: drag a rectangle to zoom to exactly that box.
- Recenter: return to the full extent of the current view.
- Download PDF (see below).
- Base-layer chooser (OSM / Google Satellite).
- Layer visibility toggles (per ward / voting districts / voting
  stations) with a Select/Deselect-All control.
- Single-ward only: "All wards" button to jump back to the overview.

LEGEND / KEY (bottom-right, collapsible)
----------------------------------------
- Ward name (single) or "All wards" title; councillor name & phone on
  the single-ward view.
- Style key: ward boundary, voting district, voting station swatches.

DEMOGRAPHICS PANEL (single ward only, top-right, collapsible)
------------------------------------------------------------
- Census pie/donut charts rendered by a self-contained SVG generator
  (piegraph.js), sized to fit and coloured from a shared palette.
- Sections: Ward Population (ward's share of the municipality),
  Population group, Employment, Age (15-64 vs rest), Education (20+),
  Monthly income, Dwelling.
- Partial percentage lists are completed with a grey "Other" slice so
  every chart reads as a full 100%.
- Wards with no data are skipped entirely.

PDF EXPORT (A4 landscape, print-ready)
--------------------------------------
Composed document (not a raw screenshot):
- Header band: Stellenbosch logo (navy) -> gold chevron -> maroon panel
  with "WARD N (year)" and the councillor's name & number.
- Left column (single ward): "WARD DEMOGRAPHICS" with the pie charts,
  auto-scaled to fit.
- Map fills the remaining area, re-rendered at the page's aspect ratio
  and framed to the current on-screen view, so everything visible on
  screen stays in frame regardless of screen size (no cropping of
  visible features).
- Map overlays: style-key legend (bottom-right, above the OSM
  attribution) and a compact data-source credit box (bottom-left:
  MDB, IEC, Stellenbosch Municipality).
- Gracefully warns if capture fails (e.g. on the Google Satellite layer,
  whose tiles can't always be captured).

RESILIENCE & UX
---------------
- Loading overlay during data fetches and PDF preparation.
- Secondary data failures never block the primary map; explanatory
  notices are shown instead.
- Responsive: controls and panels adapt to small screens.
